# Zhanlu Agent System — Gap Analysis Report

**Date:** 2026-07-16  
**Scope:** Comparison against top-tier agent frameworks (OpenAI Agents SDK, LangGraph, Anthropic extended-thinking agents, Magentic-One)  
**Overall Maturity:** ~40–55% feature breadth; ~20–30% depth/reliability

---

## Executive Summary

Zhanlu is a **broad, feature-rich ReAct agent with strong enterprise scaffolding** — it has the *surface* of a top-tier system (governance, memory, skills, sub-agents, planning FSM, swarm, tracing). But the **advanced layers are largely dormant or shallow**:

- The main conversation runtime is a **plain tool-calling loop**, not wired into the Synexia planning FSM at all.
- Memory is **keyword-overlap scoring, no semantics**.
- The "swarm" coordinator is **in-memory dataclasses, not connected to the main loop**.
- Recent bug fixes (coroutine-never-awaited ×5, `None > int` crash, missing timeouts) show the **reliability core is not battle-tested**.

## The 5 Critical Gaps (Highest Leverage)

### Gap 1 — Planning Layer is Asleep

**Impact:** HIGH | **Score:** 2/10 | **Target:** 9/10

The entire GOAL→CONTEXT→PLAN→GATE→ACT→OBSERVE→VERIFY→FINALIZE pipeline is implemented:

- `backend/app/services/synexia/fsm.py` — SynexiaFSM state machine
- `backend/app/services/synexia/plan_dag.py` — PlanDAG structure
- `backend/app/services/synexia/task_spec_parser.py` — LLM-driven task decomposition
- `backend/app/services/synexia/policy_evaluator.py` — Policy gate before execution
 — Capability-based step routing

**BUT** these are not wired into the main chat endpoint. The `add_message` / `add_message_stream` methods run a plain ReAct loop. `SynexiaFSM.run()` is only called from `executions.py`, not from the real-time conversation flow. Top-tier systems *always* plan before acting.

**Evidence:**
- Config `SYNEXIA_FSM_ENABLED` exists but behavior diverges from `is_fsm_enabled()`
- `agents.py` never imports or calls `SynexiaFSM`
- `add_message` goes directly from user input to tool-calling loop

**Remediation:** Wire `SynexiaFSM` (or a lighter planner) into `add_message` so every non-trivial request decomposes into a plan first.

### Gap 2 — Memory is Lexical, Not Semantic

**Impact:** HIGH | **Score:** 2/10 | **Target:** 9/10

`backend/app/services/memory_advanced/__init__.py` implements retrieval via **token overlap scoring**:

- Line 86: Vector similarity is declared but not implemented
- Lines 106–133: `search_memories` uses keyword-overlap (Jaccard-like) scoring
- No embedding model integration
- No recency decay, no importance weighting

**Consequence:** The agent cannot effectively "remember what the user said last week" or retrieve semantically related experiences. This limits personalization, multi-session context, and learning from past interactions.

**Remediation:** Integrate vector embeddings for memory (OpenAI `text-embedding-3-small`, or local embedding model), add recency + importance blending (`score = α·cosine + β·recency + γ·importance`).

---

### Gap 3 — No Self-Correction / Tool Retry

**Impact:** HIGH | **Score:** 3/10 | **Target:** 9/10

When a tool fails (e.g., the DB `None > int` crash recently fixed), the loop either:

1. Trips the per-tool cap guard and ends the turn
2. Returns a generic failure message

**Missing capabilities:**
- No automatic retry with exponential backoff
- No argument reformulation on failure (e.g., fix a malformed SQL query)
- No fallback to alternative tools
- No output self-verification against expectations

**Evidence:**
- `TOOL_CAP_ASK_DATA=1` causes a single rephrase to kill the data-agent turn
- The `_detect_tool_call_loop` guard is purely cardinality-based
- No `retry_with_backoff`, `reformulate_tool_args`, or `verify_tool_output` in the runtime path

**Remediation:** Add retry-with-backoff + argument reformulation in the tool-execution path; change data-agent cap keying from name-only to name+success; add output verification step.

---

### Gap 4 — Swarm is Scaffolding Only

**Impact:** HIGH | **Score:** 3/10 | **Target:** 9/10

`backend/app/services/swarm/__init__.py` defines `TeamRegistry`, `SwarmCoordinator`, and `TeamMember` as **in-memory dataclasses**. `backend/app/services/ohmo/` is an **empty stub directory**.

The main loop's topology prompts (`team`, `hierarchical`, `pipeline`) only *instruct* the LLM to coordinate — there's no actual inter-agent message bus, no mailbox, no priority queue, no handoff protocol in the runtime.

**Evidence:**
- `swarm/__init__.py` is 14 lines of dataclass definitions
- `ohmo/__init__.py` is empty
- The delegate tool works for simple pass-offs but no orchestration runtime exists
- No inter-agent communication primitives in `agents.py`

**Remediation:** Activate swarm runtime with a real mailbox, agent handoff protocol, priority queue, and shared state store.

---

### Gap 5 — Eval / Quality Gates are Undeveloped

**Impact:** MEDIUM | **Score:** 2/10 | **Target:** 8/10

`backend/app/services/synexia/confidence_scorer.py` contains `evaluation_profile` logic but the code itself notes "validation pending" (lines 75, 95). There is no:

- Automated regression test suite for agent outputs
- Golden dataset of expected responses
- Quality scoring against baselines
- A/B comparison framework for prompt/parameter changes

**Remediation:** Build eval harness on `evaluation_profile`, create golden datasets, add CI-integrated quality gates.
