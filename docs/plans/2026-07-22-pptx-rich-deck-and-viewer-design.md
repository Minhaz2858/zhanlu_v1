# PPTX Rich Deck & Inline Slide-Deck Viewer — Design

> **Status:** Design snapshot for the `pptx-generation-and-slide-deck-preview-overhaul` plan.
> Companion to the completed docx Claude-style overhaul. No new dependencies.

## 1. Goal

Turn the existing PPT pipeline into a polished, presentation-first experience:

1. **Branded generation** — decks that look professional in PowerPoint (cover, agenda, executive summary, KPI grid, chart, key findings, insights, recommendations, data table, methodology, closing) gated on `ReportCardPayload` fields, with a consistent brand theme and a per-slide footer.
2. **Positioned-HTML inline rendering** — each slide rendered at its real 16:9 geometry with shapes/colors/backgrounds/tables/images placed where python-pptx says they are, plus an inline SVG for native charts.
3. **Slide-deck viewer in chat** — one slide visible at a time on a dark stage, prev/next + keyboard navigation, a thumbnail rail, and a `N / total` counter; responsive and fast (single fetch).

**Slide catalog** (only emitted when their content exists):

| 2 | Agenda | `sections` populated | numbered list of populated section titles |

| 6 | Key Findings | `key_findings` | violet callout + numbered bullets (≤6) |
| 7 | Insights | `insights` | emoji bullets (≤6) |
| 8 | Recommendations | `recommendations` | blue callout + numbered bullets (≤6) |
| 9 | Data | `chart.data` | banded table (existing), 24-row cap + truncation note |

**Footer on every content slide (not cover):** muted 10pt `Generated by Zhanlu AI · N / total`, bottom-right. Slide number `N` is the 1-based index; `total` is the final slide count (added after all slides are built).

**Density caps:** ≤6 insights, ≤6 key findings, ≤6 recommendations, ≤6 KPIs, ≤24 data rows — match the 6×6 rule.

## 3. Positioned-HTML contract (preview_builder)

`convert_pptx_to_html(bytes) -> (html, messages)` signature unchanged. Output is one document of `<section class="zl-slide" data-slide="{1-based}">` elements.

### 3.1 Slide canvas

```
<section class="zl-slide" data-slide="N"
  style="position:relative; box-sizing:border-box;
         width:{BASE_W}px; height:{BASE_H}px; overflow:hidden;
         background:{slide bg or #ffffff}">
   ... absolutely-positioned shape divs ...
</section>
```

- `BASE_W = 960` (px). `BASE_H = round(960 * slide_height_emu / slide_width_emu)` → 540 for 16:9.
- Scale factor `PX_PER_EMU = BASE_W / slide_width_emu`. All shape `left/top/width/height` in px = `emu * PX_PER_EMU`.
- Slide background: read `slide.background.fill` solid RGB; default `#ffffff`.

### 3.2 Shape rendering

Each non-title placeholder shape becomes a `<div style="position:absolute;left;…">` with, depending on type:

- **Text frame** — emit per-run `<span>` with `font-size` (pt→px = pt × 96/72), `font-weight:bold`, `font-style:italic`, `color:#rrggbb` (from run font color; fall back to theme). Paragraph → flex column line with `text-align` (left/center/right). Bullets: prefix `• ` when `para.level>0` or bullet XML present.
- **Autoshape (rectangle)** — div with `background:{fill rgb}`, `border:{line rgb} {line_width_px}px solid`, rounded radius for `ROUNDED_RECTANGLE`. Inner text frame rendered as above.
- **Table** — a real `<table>` absolutely positioned; cell fills from `cell.fill`; header cells bold.
- **Picture** (`shape.shape_type == 13`) — `<img>` with base64 `data:` URI (content type preserved), positioned + sized. 5 MB total cap across the deck (existing behavior).
- **Title placeholder** — rendered as the first H1 of the slide (absolutely positioned, styled from its runs).

All extracted text is HTML-escaped via `html.escape` (existing). No raw slide HTML passes through.

### 3.3 Native chart → inline SVG

python-pptx cannot rasterize charts. Extract from `chart.plots[0]`:

- `categories = [str(c) for c in plot.categories]`
- series: `series.name`, `series.values` (coerce to float, `0` on failure)
- chart type from `chart.chart_type`: `COLUMN_CLUSTERED`/`BAR_CLUSTERED` → bars; `LINE` → polyline+points; `PIE` → pie slices.

Render a self-contained `<svg viewBox="0 0 W H">` (W/H from the chart shape's px size) with brand palette series colors (`#2563EB`, `#3B82F6`, `#1D4ED8`, `#60A5FA` …). Axis labels from categories, legend from series names. On any extraction failure → a labeled placeholder div (`Chart: {title}`) so the slide still reads.

### 3.4 `extract_pptx_outline` unchanged

Still returns `[{level:1, text:"<title or 'Slide N'>", id:"slide-N"}]`. The viewer keys navigation off `[data-slide]` order, so outline is informational only.

## 4. Deck viewer (PptxArtifactPreview.jsx)

Props unchanged: `{artifactId, outline, title, downloadUrl}`. ArtifactPreviewPane needs no edits; sidecar iframe precedence is preserved.

### 4.1 Data flow

1. Single `fetch('/api/artifacts/{id}/preview?format=html')` on `artifactId` change.
2. `DOMParser.parseFromString(html, 'text/html')`.
3. `useMemo` → `slides = Array.from(doc.querySelectorAll('[data-slide]'))` → array of `{id, index, html: section.outerHTML}`. Outline (if provided) supplies slide titles for the thumbnail rail; else fallback `"Slide N"`.
4. State: `current` (0-based index), `containerW`/`containerH` (ResizeObserver on the stage), `error`.

### 4.2 Stage scaling

- Base slide px = `960 × 540` (16:9) — read actual `width/height` from the parsed section's inline style for non-16:9 decks.
- `scale = min(containerW / slideW, containerH / slideH)`.
- Render `<div style="width:slideW; height:slideH; transform:scale(scale); transform-origin:top left">` containing `dangerouslySetInnerHTML` of the current slide's HTML. Transform-only → 60fps, no reflow.
- Dark stage background (`bg-[#0B1220]`), slide gets a soft shadow + 150ms opacity/scale transition on change.

### 4.3 Navigation

- On-screen: glassy pill bottom-center — prev `‹`, counter `N / total`, next `›`. Disabled at boundaries.
- Keyboard: `←` prev, `→` next, `Home` first, `End` last (attached to the pane root, not window, to avoid hijacking chat input). `Esc` does nothing (pane-level close handled by parent).
- Thumbnail rail: left `w-28` on `md+` (scrollable, numbered mini-clones scaled to ~96px wide, active ring `ring-primary`); collapses to a horizontal strip under the stage on narrow widths. Active thumbnail auto-scrolls into view. Cap at 50 thumbnails (decks rarely exceed); beyond that show a "…N more" hint.
- `outline` prop: maps `entry.id` ("slide-N") → index for the rail labels and for `onAnchorJump` compatibility (so the existing sidebar jump still works if a parent passes an outline).

### 4.4 States (reuse existing patterns)

- **Loading**: skeleton pulse on the stage (`Loader2` spinner, "Loading presentation…").
- **Error**: amber card with `Download .pptx` fallback (existing `ErrorState`).
- **Empty deck** (0 slides parsed): friendly "No slides to show" + download.

### 4.5 Performance & responsiveness

- One network request total; navigation is pure client-side.
- Thumbnails reuse the parsed DOM (clone + scale), no extra fetches.
- `ResizeObserver` (not `resize` listener) for the stage; `useMemo` for slides.
- Works from 320px (mobile chat overlay, thumbnails below) to full-height side pane.

## 5. Sandbox mirror (sandbox_runner.generate_pptx)

Bring the sparse sandbox generator (currently: title placeholder + raw data table + notes) up to the same branded deck, driven from the config fields the sandbox receives: `title, summary, source, kpis, insights, key_findings, recommendations, next_step, chart, data, methodology, sections`. All `pptx.*` imports **function-local** (module-level pptx imports fail in the worker context — same NameError class fixed previously for docx helpers). Keep `WROTE {path}` print + `report.pptx` output contract so the sandbox service persists the blob unchanged.

## 7. Blast radius & rollout

- Exporter registry, tool handlers, endpoints, dedup, sidecar logic: **untouched**.
- `ArtifactPreviewPane` props contract: **unchanged**.
- The `[data-slide]` hook is the same key the current outline jump uses, so old and new HTML both navigate during rollout.
- After backend changes: restart `zhanlu-backend` container; after JSX changes: `npm run build`; verify live preview endpoint output for a real generated deck.

## 8. Trade-offs

- Positioned HTML (chosen) gives near-pixel fidelity with zero new deps and fast loads; exotic SmartArt is not rendered (our exporter never emits it — acceptable).
- Chart→SVG covers the bar/line/pie our exporter creates; unknown chart types degrade to a labeled placeholder.
- Thumbnail rail capped at 50 to bound DOM; decks beyond that show a hint (rare).
